# 回归与安装交付规则

## 验证顺序

1. 从固定公开提交执行既有测试，保留基线结果；重构分支不能以删除或放宽旧断言换取通过。
2. 每个迁移单元验证业务规则、接口契约和真实浏览器行为。新前端执行类型检查、组件测试、lint 与生产构建。
3. 执行相关回归；涉及 HTTP、生命周期、数据库或打包时执行完整回归和成品启动检查。
4. Windows 候选包验证程序版本、源码与资源哈希、安装隔离、默认数据目录、实例锁、退出和重启。
5. 用户完成正常安装与操作验收后，记录确认与问题，再进入下一阶段。

每轮记录失败原始结果与修复后复测，不将重跑成功改写为首次通过。测试结果区分通过、失败、跳过、未运行；不把子测试与父测试相加冒充独立用例数量。合成模型/平台回执不代表真实调用质量、平台权限或播放可用。

## 强制保留的行为回归

- 后台刷新与页面切换不覆盖编辑；保存期间继续输入仍保留未保存状态。
- 文章版本冲突拒绝覆盖；原稿和修订历史在失败时保持一致。
- AI 请求保存输入快照；讨论不改稿；旧建议和撤销保护后续人工修改。
- 任务退出、重启、失败、取消和晚到响应均可解释，不产生重复派发。
- 未知送稿先核对，不自动重发；公开发表与草稿回执分开。
- 迁移前后原稿、媒体哈希、画像、历史、回执与任务归属保持；恢复不重放外部操作。
- 新 HTTP 入口保留 Host/Origin、认证、会话令牌、CSP、大小与路径限制。

## 验证版隔离

M1 首次出包前实现并验证独立 AppId、`PaperPlaneStudioPreview` 程序/安装目录、`PaperPlaneStudioPreview` 数据根、端口分配与实例锁。不能仅修改窗口标题，不能复用稳定版自动更新通道，也不能由安装器关闭或清理稳定版进程和文件。

验证版默认独立空库或合成样稿。不得自动发现并打开稳定版数据库；M1 不复制凭据、浏览器登录态或平台待执行任务。2026-10-18 用户明确授权 M2 复用配置，允许默认桌面首次启动只读原机加密配置、加密补齐验证版已有设置及账号记忆；不复制正式文章/任务、自测成功回执或浏览器用户目录，不建立双向同步。详见 M2 实施记录。若之后导入用户选定的备份，先验证复制、媒体完整性与任务暂停，导入目标仍是验证版自己的目录。稳定版数据保持原位置。

卸载验证版只移除自身程序，业务数据按明确选择保留。新旧版本的单实例保护分别验证。新旧界面共存时通过一个业务写入实例访问验证库，不能两个后台 worker 同时执行同一批任务。

## 交付记录

每个候选包需记录分支、commit、应用/阶段版本、构建环境与依赖锁、安装包 SHA256、模块/静态资源核验、测试证据、已知限制、回退方式和对应验收单。安装向导打开、安装成功、运行版本核验、用户验收四种状态分别登记。

安装包不提交进源码 Git；是否发布 GitHub Release 与是否安装均保留独立记录。稳定 `main` 不因验证分支提交自动合并。若数据库结构已改变，回退先停写并使用对应备份恢复，不直接让旧程序打开新结构。

## 公开与私密记录

仓库 Wiki 与阶段文档只包含通用说明和脱敏证据，不放个人文章、真实账号、凭据、运行数据库或私人开发台账。保持现有公开源码检查与 Gitleaks 工作流。提交前扫描待发布文件，推送后读取当前提交的 CI 结果。

本机完整日志、截图和失败样本保存在 Git 忽略的证据目录；整理到公共文档时仅保留能公开复现的结论。不能为了重新发布而重新导入安全清理前的 Git 历史。


M2 覆盖安装规则：保持验证版 AppId、EXE 和目录，固定应用与快捷方式名称；安装向导在点击安装后核验完整可执行路径并自动退出旧验证版及子进程，只替换自有程序文件，精确清理 M1 旧快捷方式。用户须先保存未保存文字；正式版程序不退出、正式数据不清理。
