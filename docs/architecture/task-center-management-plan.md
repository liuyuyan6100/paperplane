# 任务中心收纳、超时与恢复方案

2026-10-22进展：单条/批量归档、可恢复回收站和7天未变化筛选已进入`0.4.0-m4.3.2-tasks`开发候选，待用户安装验收。7天为筛选视图，不自动删除或更改业务状态。[实际操作与验收](../feature-guides/m4.3.2-task-management.md)。下文保留最初方案和当时版本的事实记录。

提出日期：2026-10-21。来源：使用者在M4.3.2安装候选中看到历史任务堆叠，要求单条或批量处理、长期未变动任务进入超时节点、删除后恢复，以及新用户流程指导。本文件是下一小单元的任务管理边界，**当前0.4.0.8和视觉引导修订0.4.0.9均未具备这些收纳操作**。P1.2选题候选仍待用户实际安装验收。

## 当前事实

任务中心现有状态筛选、搜索、类型过滤、仅当前文章和每页30项分页。截图中的10项包含失败、待审阅与已结束任务；列表不会自行清空。各种任务的原记录承担重试、审阅、送稿回执和审计用途，不能把列表清理等同于删除原任务表。配图计划已有单条归档与恢复，但不是任务中心统一收纳。

## 下一小单元建议

1. **默认聚焦当前待办**：首次打开优先显示正在执行、需处理与待确认，已结束另有分组；保留“全部”和搜索。分页计数反映当前筛选，避免因旧记录刷屏。
2. **单条与批量收纳**：对非执行中的任务提供“归档”和“移入回收站”，在对应分组可单条或批量恢复。批量操作先显示数量与类型；逐条校验并报告成功/失败数量，不因一条失败误称全部完成。
3. **自动超时分组**：建议默认**7天无状态变化**的待处理、待确认任务进入“超时待核对”。这是任务中心的视图分组，不修改原业务状态、不停止模型或送稿任务、不自动重试、不自动删除。排队、执行中、检查中以及送稿结果未知的任务须保留醒目标记；送稿未知即使长期未变动也不能据此推断未送达。
4. **恢复与原记录**：任务中心的“删除”先移到可恢复回收站；只改变列表可见性，不删除文章、输入快照、候选、图片、回执或执行日志。运行中的任务与送稿结果待核对任务不允许批量移入回收站。恢复只恢复可见性，不重启执行。永久删除必须另设明确范围和关联检查，本单元不做。
5. **新用户入口**：使用者随后要求独立按钮与视觉流程；这部分已另在同一P1.2候选修订实现，见[视觉模块指南](../feature-guides/m4.3.2-onboarding.md)。任务中心管理仍待单独实现，引导在新增或修改功能时同步更新。

## 验收边界

- 对合成数据验证单条/批量归档、回收站、恢复和分页计数；原任务表及文章修订、输入快照保持不变。
- 模拟跨过7天：非运行任务在超时分组可见，状态仍为原状态；运行中任务没有被误判停止，送稿未知仍要求先核对。
- 在另一个窗口修改任务或收纳状态时，旧页面不能按过期版本覆盖；批量操作应逐条反馈冲突。
- 重启应用后视图与收纳状态保持，恢复不调用模型或平台接口。测试使用隔离数据，不操作使用者已有任务。

本方案的7天是待验证的默认值；实现前如使用者给出不同期限，以用户要求为准。原有任务删除与配图计划归档的范围不能混淆。
