## 本轮反馈与优先验证

历史反馈：用户实际体验M3.1后指出文章信息缺少AI补齐入口、任务中心用途不清楚，M3.2已修正。历史记录显示异常另经核对为Windows打包应用目录隔离导致读取不同库，原历史已备份并追加恢复，运行中桌面接口回读通过；随后用户明确确认M3测试通过。恢复详情仅保存在本机证据，不公开私人数据库。

1. 打开有正文的测试文章，选好账号画像并保存一次。展开“摘要、署名与更多信息”，点击“AI补齐空白信息”。沿用已有文字模型；这是一次正常模型调用。
2. 等待建议，核对摘要、标签和署名来源。署名来自同画像既有文章或画像中的已有信息；无依据时留空。已有手填内容保留，来源与封面仍由你核实。
3. 点击“确认填入空白处”，应只填空白的摘要、署名和标签，正文不变。可以直接在字段中修改，再点击“保存文章”。重开确认仍在；取用过的建议自动收起。
4. 另一次生成期间继续改正文或署名，旧建议应提示依据变化、无法直接填入；用“按当前稿重新补齐”处理新内容。
5. 顶部出现“本篇：处理中／待确认／需处理”时点击，应只看当前文章。文章信息补齐记录会指向文章信息区，普通侧栏讨论仍在侧栏查看。

**任务中心是处理进度和异常记录。** 发送AI请求后自动留下记录，不要求你先建任务。正在处理时可以继续写；待确认表示等你审阅，需处理表示失败、中断或结果待核对。日常编辑不必一直打开任务中心，查看状态本身不调用模型。它不会自动采用或发表文章。

## 先用已有记录验证

| 操作 | 应看到的结果 | 用户结果 |
| --- | --- | --- |
| 打开已有测试文章，查看模型/画像设置 | 原文章、对话、原模型和配置保留 | 待确认 |
| 点顶部“任务中心” | 能看到M2留下的编辑对话；类型、原编号、状态与时间可查看 | 待确认 |
| 选一条历史记录 | 讨论显示已回复，已有取用记录与待审建议区分；不把取用显示成已保存或已发表 | 待确认 |
| 切换“需处理 / 待确认 / 已结束”，选择类型、搜索或勾选仅当前文章 | 列表与计数随范围变化，原任务未新建或清理；没有匹配时明确显示为空 | 待确认 |

列表数字按业务记录计算。一篇文章可能有创作、检查、配图和送稿等多条记录，数量不代表模型调用次数。已归档或回收站内容仍从原工作台查看。

## 查看执行过程，同时保护编辑内容

1. 在测试稿正文加一句未保存文字；在侧栏“仅讨论”询问这句话是否清楚，按Ctrl+Enter。沿用当前原模型配置，此操作会正常调用你选择的模型。
2. 发送后打开任务中心，选择“编辑对话”并查看对应记录。处理较快时可能直接看到“已回复”，不要求为了截图重复发送。状态读取本身不调用模型。
3. 查看其他任务、刷新状态、关闭面板。正文未保存修改和之后写在AI框里但尚未发送的要求都应保留。点击当前文章的“打开所属文章”只返回当前编辑区，不重新加载丢掉文字。
4. 手动保存需要保留的文字，完全退出并重开验证版，再查看同一记录。原编号与结果保留，不因查看、重开而另生成一条。

## 有失败、中断或送稿待核对时

| 情形 | 操作及边界 | 用户结果 |
| --- | --- | --- |
| 明确失败或中断的创作/文字助手 | 核对原要求与错误；需要恢复时点“重试原任务”，保持原ID及输入快照，不自动采用正文 | 有此情形时核对 |
| 配置或权限错误 | 到已有配置入口处理，回任务再主动重试；本轮不要求重填已有配置 | 有此情形时核对 |
| 创作停在待确认提纲 | “到原工作台处理”直接进入原任务，确认之前不生成正文 | 有此情形时核对 |
| 送稿结果待核对 | 不提供直接重试；有可核对的原草稿编号时先只读核对，否则去原平台检查 | 有此情形时核对 |
| 人工确认平台确实未收到 | 明确勾选后“标记为未收到”；只改核实状态，随后仍须主动点重试才发送 | 有此情形时核对 |
| 取消允许取消的任务 | 状态变为已取消；已发出的模型请求可能继续，晚到内容不采用、不覆盖后续状态 | 有此情形时核对 |

**不需要为了验收故意破坏模型配置、强杀生成任务或再次真实送稿。** 失败、中断、去重与未知送稿的危险分支已用隔离合成数据作故障回归，具体证据见[实施记录](03-tasks-implementation.md)。真实平台权限和当前草稿接收结果仍须按实际证据核对。

M3只统一任务查询和安全恢复，不自动采用、保存或公开发表。原工作台仍承载尚未迁入的新功能；打开它的独立页面不会替换当前编辑器。M3现已用户确认通过，下一阶段按既有计划进入M4功能与数据兼容；该确认不代表未迁入功能或真实平台播放、权限与公开发表已经验通。
