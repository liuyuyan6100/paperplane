# 功能保留与版本差异

公开分支从 `4b35c6d` 开始，应用标记为 0.1.76。较新本地候选版本为 0.1.77，二者内容不完全相同；版本号大小不能替代文件和功能对照。

本清单约束“不能遗漏”，不表示全部功能已经迁入新框架。M0 没有改动运行代码，当前仍是公开基线的原行为。

## 第一条链路

| 能力 | 必须保留的语义 | 迁移阶段与验证 |
| --- | --- | --- |
| 文章列表与打开 | 列表/详情关联同一文章 ID；切换后的迟到响应不能显示旧对象 | M1；确定性延迟与导航测试 |
| 编辑与保存 | 保留正文、标题、作者、摘要、画像、标签、媒体引用；版本校验、修订历史与未保存修改保护 | M1；两窗口冲突、保存期间继续输入、重开、Unicode/Markdown |
| 后台刷新 | 不能覆盖正在输入的编辑区；安全清理后新增的状态刷新保护继续生效 | M1；沿用 `tests/test_state_refresh.py` 并增加新界面对应行为测试 |
| 侧边讨论 | 基于当前工作项和未保存内容；讨论不改原稿 | M2；请求快照和界面断言 |
| AI 修改 | 明确全文/选区；对照、采用到编辑区、撤销；旧结果不覆盖后续人工修改 | M2；迟到结果、切换文章、失效选区、连续修改 |
| 提纲与待审稿 | 提纲确认后生成正文；候选采用后更新原稿；输入和画像快照保留 | M2/M4；原工作流回归继续运行 |
| 状态与恢复 | 保留原任务身份、阶段、错误和结果；中断后人工继续；未知送稿核对后才允许重试 | M3；崩溃、断流、取消竞争、旧 run token |

## 其他现有能力

画像与历史、已确认记忆及候选学习、素材与共享资料库、配图与候选采用、平台改编、送稿准备与草稿回执、渠道配置、公众号原生视频关联、备份恢复、托盘与服务器连接等，保留旧入口及对应回归。每项新实现等价验证前不能删除原实现。

保留不等于承诺外部平台全部可用。API 权限失败、人工视频上传、实际播放和平台发表仍按现有证据边界处理；不能因迁移而将未验通的功能标为验通。

## 较新本地候选的归并清单

以下来自较新候选的代码与实施记录，尚未合入本公开分支，也不等于用户已安装或验收：

| 能力 | 涉及模块示例 | 处理方式 |
| --- | --- | --- |
| 集中故障与恢复 | `studio/recovery.py`，原任务运行令牌与恢复路径 | M3 前逐项比较，保留回执与晚到结果保护，不用旧公开行为覆盖较新修复 |
| 运营指标采集 | `studio/metric_collection.py`、复盘相关界面 | M4 归并；缺失与零值区分，权限不足保留手填，不额外新增自动调度 |
| 配音与成片 | `studio/media_production.py`、`web/productions.js` | M4 归并；脚本确认、产物预览、明确采用，保留原件 |
| 原生视频交接与验收 | `studio/videos.py`、`web/videos.js` 等 | M4 归并；关联原生草稿、人工播放确认，不将 API 素材回读视为播放成功 |

这是一份重点差异清单，不是完整补丁清单。较新本地源码还包含安全清理、格式与其他功能差异，不能整目录覆盖或将私人 Git 历史合入。本分支的公开安全检查和后台刷新修复优先保留；迁入补丁必须逐项审查、脱敏、回归，再提交公开分支。

## 完成判定

每项保留能力分别记录：原版本证据、迁入提交、自动测试、安装验证、用户反馈、外部服务限制。只有全部必要项目已有结论，才可把架构验证版作为稳定版替换候选。
