# Aiclaw 跨平台视觉风格包

本包保存用户认可的“Aiclaw 温暖工程手绘”风格。可用于纸飞机、Easel 或其他支持自定义创作指令的平台，无需绑定某一家生图模型。

## 文件

- `reference-cover.png`：原始风格基准图，勿覆盖。
- `STYLE.md`：视觉规范与封面、正文插画、解释图、图卡的区别。
- `PROMPTS.md`：可复制提示词与交给其他平台的导入指令。
- `style.json`：可由程序读取的风格 ID、色板、范围、建议画幅与资源路径。它是本包的交换格式，不是所有平台都原生支持的标准。
- `easel-style.json`：按当前本机 Easel 公众号配图技能结构生成的原生风格配置。
- `manifest.json`：包内文件 SHA256，用于核对各端是否拿到同一版本。

## 其他平台怎样使用

1. 同时导入参考图和 STYLE.md；平台只有偏好文本框时，复制 PROMPTS.md 的共用段，把图片放在可访问的素材区。
2. 将这套规则绑定到 Aiclaw 对应画像，不设置为所有用户或账号的默认值。
3. 为具体图片填写主题、准确文案与画幅，并传入参考图。文件放进知识库不代表生图工具已经拿到图像。
4. 首次换平台或模型，用同一主题生成一张小样，人工比较画法、色板、标题和信息准确性，再沿用到整组。

## Easel 接入（可选，当前上游未实测）

以下路径来自历史本地集成，**不保证当前 Easel 上游存在相同技能或参数**。请先对照所用版本的技能说明；没有对应入口时使用上面的文本与参考图导入方式，不要盲目复制路径。

历史集成将本包放在画像目录的 `assets/visual-style/`。在该画像 `style.md` 写入风格摘要和资源入口。把 `easel-style.json` 复制为公众号配图技能 `assets/image-styles/aiclaw-warm-engineering.json`，并检查运行时读取的技能副本也有该文件。

在本画像的文章或图卡 brief 中显式写入 `image_style: aiclaw-warm-engineering`，避免被技能的通用默认风格覆盖。Easel 的风格 JSON 主要提供文字提示；其生图入口的 `--ref` 参数才负责传递实际参考图，不能把 JSON 中的一个路径字段误当作图像输入已接通。

其他 Easel 制作技能（正文插画、小红书卡片等）仍需从画像读取 STYLE.md，并向它们实际使用的生图工具传图。这份注册不会自动修改所有技能的内部默认值。

本包不包含 API Key，不会购买生图服务，也不会自动发布或发送内容。跨平台复制后应核对版本；当前提供的是可移植风格包，没有后台自动同步服务。

## 纸飞机接入

本次验证资源被源码、Windows 包与主 Docker 镜像包含，并校验 manifest；真实生图效果与其他平台集成未实测。

现有画像的表达风格可以保存文字摘要。若生成流程只传文本、没有把参考图送到生图模型，仅能说明文字偏好已注入。完整接入应让本次图片任务保存风格 ID、版本、参考图及实际生成参数，再验证结果。本包不把本地文档保存等同于云端运行功能已实现。
