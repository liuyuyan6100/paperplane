# 功能使用与验收指南

照着步骤学会使用，再对照预期结果检查功能。适用于本仓库架构验证分支；稳定版和不同版本的按钮可能不同。每篇标明适用版本，历史截图保留拍摄时的界面。

**第一次使用：先新建或打开一篇测试文章，填写标题、正文并点击“保存文章”，再进入依赖已保存文章的创作功能。** 保存文章、保存提纲、保存待审稿和采用正文是不同的操作，详见[M4.1完整练习](m4.1-text-creation.md)。

## 每次验收怎样收录

1. 按[模板](TEMPLATE.md)建立或更新功能指南，写清版本、入口、准备、示例、操作、预期结果、常见问题和数据影响。给测试步骤固定编号，后续反馈能直接指向同一步。
2. 每轮在`records/`新增有日期的验收记录，逐项写实际结果、截图、问题、修复与复验。尚未操作的项目写“待验证”，没有单项反馈不补写为单项通过。
3. 截图放`assets/<阶段>/`，在正文注明来源、时间、版本和场景。用户反馈截图与隔离自动测试截图分别说明；失败截图不冒充正常操作或验收成功。
4. 更新上表、阶段验收入口和Wiki链接。功能变化更新指南，旧验收记录和问题历史保留。自动测试、安装完成、用户确认分别登记。
5. 公开前查看截图和文字，保留可复用的操作说明。使用练习文章；含凭据、私人正文或账号信息的材料先处理后再发布，原始数据库与完整运行日志留在本机证据目录。

后续每次交付均按此方式积累，无需每轮另建一套使用说明。需要反馈时，复制对应记录表，填“通过 / 失败 / 未测”和实际现象即可。完整开发方测试说明仍见[开发测试](../../tests/README.md)及[回归与交付规则](../architecture/validation-and-release.md)。
